# RISK_OFF short-strategy shadow research track

Date: 2026-11-24. Status: **SHADOW ONLY — no policy change, no orders**.

## Why this track exists

Today's short setups were detected correctly (9 `short_breakdown` candidates
at 10:45 ET) but none were executable. The approved bearish entry path is an
options PUT under `RISK_OFF`, and options are blocked by the VIX > 25 rule
(VIX 27.3–29.0). In equity mode a bearish signal is treated strictly as an
exit; with zero positions held there is nothing to sell. No approved
long/short entry strategy is eligible in today's regime.

This is a research track to learn whether a dedicated short strategy could
ever justify a policy change. It is not permission to short.

## Proposed strategy (candidate, not approved)

1. **Opening-range breakdown** — price closes below the 09:30–09:45 range low.
2. **VWAP rejection** — price below session VWAP and below the fast EMA.
3. **Relative weakness vs SPY** — ticker return underperforms SPY over the
   same window (point-in-time, prior-session data only).
4. **Downtrend confirmation** — SPY 50/200d regime `RISK_OFF` (desk-wide
   regime classifier) and price below the value area / POC.
5. **Liquidity + borrow** — minimum ADV/dollar-volume filter; borrow cost
   charged per day in the backtest; borrow availability must be verified at
   execution time before any entry (never assumed).
6. **Risk** — stop above OR high or ATR multiple, target at >= 2R, sizing
   within existing per-order and portfolio caps, entry cutoff 15:15 ET,
   flatten 15:45 ET.

## Backtest method

Reuse `scripts/daytrade_backtest.py`, which replays the *real* pipeline in
order: scout (OR/VWAP) → zone confluence → odds gate (stubbed, see caveat)
→ sizing and R:R → risk controller (isolated temp ledger) → simulated fill
and exit with commission, slippage and borrow cost. No look-ahead; the regime
uses SPY closes through the prior session.

Real-data runs (yfinance 5m, TradingAgents venv, 2026-11-24):

Evidence: **insufficient**. There are **zero RISK_OFF short samples** in the
available 5-minute history; the observed short trades are all RISK_ON and net
negative after costs. yfinance serves ~60 days of 5m bars, so a longer
RISK_OFF sample requires a different historical intraday source or a
forward-looking shadow collection.

The shadow report is generated by `scripts/risk_off_short_research.py`:

```
python scripts/daytrade_backtest.py --days 60 --out <bt.json>
python scripts/risk_off_short_research.py --bt-json <bt.json> --out outputs/research/risk_off_short_shadow.json
```

The report carries `shadow_only: true`, `orders_submitted: 0`,
`enforcement_enabled: false`, and `entry_permission: none`.

## Gate to any future policy change

Before anyone proposes allowing short entries under desk-wide RISK_OFF:

1. Collect a statistically meaningful set of RISK_OFF short samples in shadow
   mode (target >= 30, with borrow availability recorded per candidate).
2. Re-run the backtest with the relative-weakness filter and pre-registered
   stop/target rules; report win rate, profit factor, drawdown and costs.
3. Obtain a documented policy update, tests, and explicit owner approval.
4. Only then consider an implementation behind the existing deterministic
   gates and a separately authorized execution path.

A bearish analyst recommendation remains research, never an order.
